# 配線設計のプロンプト

UIAPduino Pro Micro CH32V003 V1.4と、完成・人確認済みの`REQUIREMENTS.md`をもとに、自由制作`device1`の配線案を設計してください。

この段階では配線設計だけを行います。

次は生成しないでください。

* プログラム
* Makefile
* `funconfig.h`
* `usb_config.h`
* PC側プログラム

## 添付資料

* `BOARD_FOR_AI.md`
* `PARTS_FOR_AI.md`
* `REQUIREMENTS.md`
* `MY_DEVICE_TEMPLATE/WIRING.md`

必要な場合は、`REQUIREMENTS.md`で明示された参考演習・PoCの資料も添付します。

## 用語

この作業では、次を区別してください。

* `未確認`

  * 今回の設計に必要だが、資料から確認できていない状態
* `該当なし`

  * 今回の構成ではその確認自体が必要ない状態

`未確認`を`該当なし`として扱わないでください。

安全性または実現可否に関係する項目が`未確認`の場合は、安全側へ推測して配線案を完成させず、原則として`要確認`としてください。

## 最初にREQUIREMENTS.mdを確認する

配線設計を開始する前に、`REQUIREMENTS.md`を実際に読み、次を確認してください。

### 人による要件確認

次のすべてを満たす必要があります。

* `要件の状態`が`合意済み`
* `受講者確認`が`確認済み`
* `確認日`が記載されている

### 配線設計開始条件

次のすべてを満たす必要があります。

* `配線設計へ進む前の確認事項`が`なし`
* 安全性または実現可否に関係する`未確認`が残っていない
* 使用部品と数量が確定している
* 入力が確定している
* 出力が確定している
* PCとの連携要否が確定している
* 必要な安全条件が記載されている

1つでも満たさない場合は`要確認`として停止してください。

配線案を推測で作成しないでください。

## 資料が矛盾する場合

資料同士が矛盾する場合は、優先順位で推測して解消しないでください。

次を示して`要確認`として停止してください。

* 矛盾している資料
* 矛盾している項目
* なぜ設計を続けられないか
* 何を確認または修正すれば再開できるか

## 会話で要件変更が指定された場合

今回の会話で`REQUIREMENTS.md`の内容を変更する指示が追加された場合は、`WIRING.md`へ直接反映しないでください。

例えば次です。

* 使用部品を変更する
* 数量を変更する
* 入力を追加・変更する
* 出力を追加・変更する
* PC連携方式を変更する
* 対象OSを変更する
* 動作仕様を変更する
* 安全条件を変更する
* 今回作らない機能を追加する

この場合は、

`要確認`

として停止し、先に`REQUIREMENTS.md`の修正と人による再確認が必要であることを示してください。

## 使用部品の扱い

使用部品と数量は`REQUIREMENTS.md`を正本としてください。

生成する`WIRING.md`の`使用部品`には、`REQUIREMENTS.md`の内容を転記してください。

次を独自に変更しないでください。

* PART-ID
* 名称
* 数量
* 使用機能

不一致がある場合は`REQUIREMENTS.mdとの整合確認`を`不一致`とし、配線案を完成させず`要確認`として停止してください。

販売ページや一般的な同名部品・類似製品の仕様を、今回配布する部品の確定仕様として使用しないでください。

## 設計時に必ず確認すること

### GPIO

* 使用GPIO
* UIAPduino基板表記
* ch32fun端子名
* 入出力方向
* GPIO重複利用
* GPIOの起動時状態

### 周辺機能

* ADC
* PWM
* タイマー
* DMA
* SPI
* I2C
* USB

使用する周辺機能について、

* 使用GPIO
* 使用資源
* 他機能との競合

を確認してください。

### UIAPduino固有の制約

最低限、次を確認してください。

* PC0 / D2の基板上LEDとの競合
* PD1 / D11をSWIO用として原則予約できているか
* rv003usb使用時にPD3 / PD4 / PD5を他用途へ割り当てていないか
* 基板左右の同名7 / 8 / 9端子を別GPIOとして扱っていないか
* `BOARD_FOR_AI.md`に記載されたその他のGPIO・周辺機能制約

### 電源と信号

* UIAPduinoのマイコン電源電圧
* 各部品の電源電圧
* 信号電圧
* GPIO入力電圧
* GPIO出力電圧
* GPIOから取り出す電流
* GPIOへ流し込む電流
* 部品の必要電流
* USB電源容量への影響
* GND共有
* 部品の最大定格

### 補助回路

必要性を確認してください。

* プルアップ
* プルダウン
* LED等の電流制限抵抗
* モーター等のドライバー
* 逆起電力対策
* ノイズ対策
* その他の保護回路

### 極性と向き

* 電源極性
* LED極性
* ダイオード極性
* 電解コンデンサ極性
* トランジスタ・MOSFETの端子
* センサー・モジュールの向き
* その他の部品固有の向き

### 起動・停止時の安全状態

最低限、次を定義してください。

* 電源投入直後からGPIO初期化完了まで
* GPIO初期化完了後の通常待機
* 利用者による操作中
* USB切断時
* 通信異常時
* プログラム異常時
* 利用者が停止したとき

### 初心者が誤配線しやすい箇所

少なくとも次を確認してください。

* VCCとGND
* 似た端子名
* 基板左右の同名7 / 8 / 9
* 部品の極性
* 部品の向き
* ブレッドボードの列
* 誤配線すると過電流などにつながる接続

## 「問題なし」の根拠

電圧、電流、定格、GPIO、周辺機能、安全性などについて`問題なし`と判断する場合は、今回渡された確認済み資料を根拠としてください。

主な根拠は、

* `BOARD_FOR_AI.md`
* `PARTS_FOR_AI.md`
* 確認済み参考演習・PoC

です。

安全性に必要な数値や条件を確認できない場合は、一般知識や類似製品から推測して`問題なし`にしないでください。

`未確認`

として扱ってください。

## USB通信を使用する場合

USBを使用する場合は、`WIRING.md`の`USB通信を使う場合`を完成させてください。

一般知識から次を推測しないでください。

* USBスタック
* VID
* PID
* Usage Page
* Usage
* Report ID
* Report長
* Report方向・種類
* Reportの各バイトの意味
* PC側との通信形式

`REQUIREMENTS.md`または明示された確認済み参考演習・PoCから根拠を確認できる場合だけ記載してください。

### USBスタック

このDevkitでUSBを使用する場合は、確認済み資料に別の決定がない限りrv003usbを前提とします。

ただし、実際の参考実装を確認せずにrv003usbのコードや設定を生成してはいけません。

### USB Report

Reportを使用する場合は`USB Report`表へ1 Reportにつき1行で記載してください。

最低限、

* Report ID
* 方向・種類
* 長さ
* Reportの内容
* 各バイトの意味

を確認してください。

複数Reportがある場合はすべて記載してください。

### USB用GPIO

rv003usbを使用する場合は、

* PD3
* PD4
* PD5

がUSB用として予約され、他用途と競合していないことを確認してください。

USBを使用しない場合はUSB関連項目を`該当なし`としてください。

## 使用部品の未接続端子

使用する部品に未使用端子がある場合は、

* 端子
* 処理方法
* 根拠

を記載してください。

処理方法の例:

* 未接続
* GNDへ接続
* VCCへ接続
* 抵抗を介して固定

根拠を確認できない場合は`未確認`としてください。

UIAPduinoの使用しないGPIOをすべて列挙する必要はありません。

ただし、安全上特別な状態へ設定する必要があるGPIOは記載してください。

## 設計可否の判定

最初に、次のどちらかを示してください。

* `配線案作成可能`
* `要確認`

### 配線案作成可能

これは、

**今回渡された資料を根拠として配線案を作成できる**

という意味です。

人による配線安全確認が完了したことを意味しません。

### 要確認

次のいずれかに該当する場合は`要確認`としてください。

* `REQUIREMENTS.md`の人による確認が完了していない
* `配線設計へ進む前の確認事項`が`なし`ではない
* 安全性に必要な仕様が`未確認`
* 実現可否に必要な仕様が`未確認`
* 資料同士に矛盾がある
* 使用部品または数量が不一致
* 必要なGPIOが不足している
* GPIOが競合する
* タイマー等の周辺機能資源が不足または競合する
* 電源電圧を判断できない
* 信号電圧を判断できない
* 電流条件を判断できない
* 必要な補助回路を確定できない
* 部品の極性や端子を確認できない
* 必要なUSB仕様を確認できない
* 安全な起動・停止状態を確定できない
* その他、安全な配線を確定できない

## 要確認の場合

`要確認`の場合は配線案を推測で完成させないでください。

各項目について次を記載してください。

| 項目           | 内容 |
| ------------ | -- |
| 未確認・矛盾していること |    |
| なぜ確認が必要か     |    |
| 確認方法         |    |
| 配線設計を再開できる条件 |    |

複数ある場合は項目ごとに記載してください。

その後、処理を停止してください。

次は出力しないでください。

* 仮の配線表
* 推測したGPIO
* 仮の抵抗値
* 仮のUSB仕様
* プログラム
* Makefile
* `funconfig.h`
* `usb_config.h`
* PC側プログラム

また、次へ進むよう案内しないでください。

* 実物の配線
* 通電
* ファームウェア書き込み
* プログラム生成
* 実機確認

## 配線案作成可能な場合

`MY_DEVICE_TEMPLATE/WIRING.md`の見出し・表構造をそのまま維持して、今回の`WIRING.md`を完成させてください。

独自の見出し構造へ置き換えないでください。

### 配線案の状態

次のようにしてください。

* `AI設計判定: 配線案作成可能`
* `判定時の未確認事項: なし`

### 配線表

1接続を1行としてください。

UIAPduinoへ接続する場合は、可能な限り、

* UIAPduino基板表記
* ch32fun端子名

の両方を記載してください。

各接続について最低限次を明確にしてください。

* 部品
* 部品側端子
* UIAPduino基板表記
* ch32fun端子名
* UIAPduinoから見た方向
* 電圧
* 論理・機能
* プルアップ / プルダウン
* 抵抗・補助回路
* 起動時状態

同じGPIOを複数接続で共有する場合は、意図した共有なのか競合なのか説明してください。

## 配線手順

`WIRING.md`には初心者向けの配線手順も記載してください。

ただし、これは人による配線安全確認後に実行する手順です。

手順の冒頭で、

`配線安全確認が確認済みになるまで実行しない`

ことが分かるようにしてください。

## 未確認事項

`配線案作成可能`の場合は、`WIRING.md`の`未確認事項`について、安全性または実現可否に関するものが残っていてはいけません。

ない場合は明示的に、

`なし`

としてください。

`該当なし`と`未確認`は区別してください。

## 配線安全確認の扱い

生成AIは、人による配線安全確認を代行しません。

生成AIが資料上の配線に問題がないと判断しても、生成する`WIRING.md`では、

* `状態: 未確認`
* `確認者:` 未記入
* `確認日:` 未記入

のままにしてください。

### 初回生成時

プログラムがまだ存在しない初回の配線設計では、

* `確認対象: 初回プログラム生成前`
* `再確認対象のプログラム版: 該当なし`

としてください。

### プログラム修正後の再確認

後でプログラム修正によって、

* GPIO
* GPIO方向
* 起動状態
* 停止状態
* 出力条件
* USB仕様
* その他の電気的安全性

が変化した場合は、人による配線安全確認を再度行います。

その場合は、

* `確認対象: プログラム修正後の再確認`
* `再確認対象のプログラム版: （対象版）`

として扱います。

生成AI自身が`状態: 確認済み`へ変更してはいけません。

生成AI自身を`確認者`として記載してはいけません。

## 次工程へのゲート

配線安全確認が`確認済み`になるまでは、次へ進むよう案内しないでください。

* 実物の配線
* 通電
* ファームウェア書き込み
* プログラム生成
* PC側プログラム生成
* 実機動作試験

生成直後の`WIRING.md`は人による確認前です。

プログラム生成へ進むには、受講者または講師が内容を確認し、少なくとも次を満たす必要があります。

* `AI設計判定: 配線案作成可能`
* `配線安全確認`の`状態: 確認済み`
* `確認者`が記載されている
* `確認日`が記載されている
* `確認対象`が記載されている
* 初回の場合、`再確認対象のプログラム版: 該当なし`
* `未確認事項: なし`
* 安全性または実現可否に関係する`未確認`がない

## 出力

次の順で出力してください。

1. 設計可否

   * `配線案作成可能`
   * または`要確認`
2. 要確認事項

   * ある場合だけ記載
3. `配線案作成可能`の場合だけ、完成した`WIRING.md`全文

`要確認`の場合は`WIRING.md`の完成版を推測で出力しないでください。

プログラム、Makefile、`funconfig.h`、`usb_config.h`、PC側プログラムは出力しないでください。
