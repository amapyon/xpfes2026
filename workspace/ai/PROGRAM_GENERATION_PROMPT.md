# device1 プログラム生成用プロンプト

UIAPduino Pro Micro CH32V003 V1.4、
ch32fun、必要な場合はrv003usbを使って、
自由制作device1のプログラム一式を生成してください。

初心者が短時間で
「ビルドする → 書き込む → 動かす」
ところまで到達できることを優先してください。

## 今回の入力

- REQUIREMENTS.md
- WIRING.md

利用経路:

ローカル操作型 / Web・手動受け渡し型

## 基本方針

REQUIREMENTS.mdを、

「何を作るか」

の正本として扱ってください。

WIRING.mdを、

「どの部品をどのGPIOへ接続するか」

の正本として扱ってください。

ただし、これらは契約書ではありません。

ソフトウェア実装上の細かな事項が書かれていない場合は、
合理的な方法を選んで実装してください。

例えば次は生成AIが決めて構いません。

- 変数名
- 関数構成
- デバウンス方法
- ポーリング周期
- HID Reportを送るタイミング
- USB Descriptorの実装方法
- 軽微なタイミング値
- エラー処理方法

利用者の意図や物理配線を変えない限り、
確認のために停止する必要はありません。

## 利用できる開発基盤

原則として次を使用してください。

### MCU

- CH32V003
- ch32fun

### USBを使う場合

- rv003usb

Devkitで採用していないUSBスタックを、
新たに導入しないでください。

例:

- TinyUSB
- Arduino USB API
- WCH HAL USB

Devkit外の追加ライブラリを
インターネットからインストールすることを前提にしないでください。

## 最初に確認すること

REQUIREMENTS.mdとWIRING.mdを読み、
次だけ確認してください。

1. 作りたい動きが分かる
2. 使用する部品が分かる
3. GPIO配線が分かる
4. WIRING.mdの`設計結果`が`要確認`ではない
5. REQUIREMENTS.mdとWIRING.mdに安全上の`要確認事項`が残っていない

問題がなければ、すぐプログラム生成へ進んでください。

人による承認状態、確認者、確認日などは要求しないでください。

## 要確認で停止する場合

次の場合だけプログラム生成を停止してください。

- WIRING.mdが`要確認`
- 電源やGPIOについて危険な矛盾を発見した
- REQUIREMENTS.mdとWIRING.mdで使用部品が食い違っている
- WIRING.mdに必要なGPIOが書かれておらず、合理的に判断できない
- 必要なUSB実装情報をDevkitまたは参考実装から取得できない
- 指定された機能がCH32V003では実現できない

軽微な実装上の選択肢があるだけでは停止しないでください。

## REQUIREMENTS.mdとの関係

次は変えないでください。

- 作りたい動き
- 使用部品
- 入力
- 出力
- PCとの連携目的

ただし、要件を実現するためのソフトウェア詳細は
生成AIが決めて構いません。

## WIRING.mdとの関係

次は一致させてください。

- ch32fun端子
- GPIO方向
- Active Low / Active High
- プルアップ / プルダウン
- ADC / PWMなどの用途
- USB用予約GPIO

### 軽微なWIRING.mdの修正を発見した場合

例えば、

- 表記ミス
- ch32fun端子名の単純な誤記
- ソフトウェア上必要な説明不足

であり、

- 電源
- GND
- 部品
- GPIOの物理接続
- 保護回路
- 極性

を変更しない場合は、
修正内容を明記した上でプログラム生成を続けて構いません。

### 物理配線の変更が必要な場合

次が変わる場合は停止してください。

- 使用GPIO
- 電源
- GND
- 極性
- 抵抗
- ドライバー
- ダイオード等の保護回路

その場合は、

`配線修正が必要`

とし、修正版WIRING.mdを提示してください。

## 参考実装

REQUIREMENTS.mdまたはWIRING.mdに
参考演習・PoCが記載されている場合は、
できるだけその実装を起点にしてください。

特にUSBでは、確認済み参考実装を優先してください。

USBを使用する場合は必要に応じて次を参考実装から確認してください。

- rv003usbの組み込み方
- Makefile
- funconfig.h
- usb_config.h
- Usage
- Report Descriptor
- Report ID
- Report長
- PC側プログラムとの通信形式

WIRING.mdにこれらの詳細が書かれていなくても問題ありません。

プログラム生成時に参考実装から決定してください。

### ワークショップ共通のUSB識別子

USBアプリケーションのVIDとPIDは参考実装の値を流用せず、必ず次に固定してください。

- VID: `0x1209`
- PID: `0x0001`

`1209:0001`はpid.codesの共有テスト用識別子であり、世界で一意ではありません。教育目的の試作と、このワークショップ内のテストだけに使用します。製品、製造、販売、再配布には使用できません。

VIDとPIDを定義または直接埋め込むファームウェア、PC側プログラム、設定ファイルには、この制限を示す警告コメントを必ず記載してください。

Product文字列は演習ごと、参加者の自由制作ごとに設定します。ファームウェアとPC側プログラムで同じProduct文字列を使用し、自由制作ではデバイス名を基にした識別しやすい文字列にしてください。

ブートローダーの`1209:B803`は変更しません。通常アプリケーションの`1209:0001`と混同しないでください。

## Makefile

次を起点にしてください。

`workspace/ai/MY_DEVICE_TEMPLATE/Makefile`

原則としてDevkitの既存構成を維持してください。

- UIAP_PLATFORM
- UIAP_WORKSPACE
- UIAP_RUNTIME
- ch32funの参照方法
- TARGET_MCU := CH32V003
- MCU_PACKAGE := 1
- PREFIX := riscv-none-elf
- make
- make size
- make flash

OS固有の絶対パスを埋め込まないでください。

USBを使用する場合だけrv003usbを追加してください。

## プログラムで守ること

- 主ソースは`device1.c`
- ch32funを使用する
- WIRING.mdのGPIOと一致させる
- 起動直後に意図しない出力を出さない
- 起動直後に意図しないUSBキー入力等を送らない
- スイッチには必要に応じてデバウンスを入れる
- WIRING.md指定のプルアップ / プルダウンを使用する
- USB不要ならrv003usbを追加しない
- PC側プログラム不要ならhost/を作らない
- REQUIREMENTS.mdで要求していない機能を勝手に増やさない

基本構成:

```text
device1/
├── README.md
├── REQUIREMENTS.md
├── WIRING.md
├── Makefile
├── device1.c

```

必要な場合だけ追加してください。

- usb_config.h
- 追加の.c
- 追加の.h
- host/

## README.md

初心者が次に何をすればよいか分かる内容にしてください。

最低限次を記載してください。

- 何を作ったか
- 使用部品
- WIRING.mdへの参照
- ビルド
- 書き込み
- 動作確認
- 停止方法
- 参考にした演習・PoC

コマンドにはプロンプト記号を付けず、
そのままコピーできる形にしてください。

基本コマンド:

```sh
make
make size
make flash
```

## ローカル操作型

ローカル操作型では、
Devkit内のファイルを実際に読んでください。

最低限確認するもの:

- workspace/ai/BOARD_FOR_AI.md
- workspace/parts/PARTS_FOR_AI.md
- workspace/my/device1/REQUIREMENTS.md
- workspace/my/device1/WIRING.md
- workspace/ai/MY_DEVICE_TEMPLATE/
- 必要な参考演習・PoC

編集は原則として、

`workspace/my/device1`

だけに限定してください。

ファイル生成後は可能なら次を実行してください。

```sh
make clean
make
make size
```

ビルドエラーが出た場合、
REQUIREMENTS.mdや物理配線を変更しなくて済む範囲なら、
生成AI自身で修正して再ビルドしてください。

エラーごとに利用者へ確認を求める必要はありません。

## Web・手動受け渡し型

AI_HANDOFF_MANIFEST.mdまたはAI_HANDOFF.mdがある場合は、
そこに含まれる資料を使用してください。

受講者PC上で実際に、

- ビルドした
- 書き込んだ
- USB認識を確認した
- 実機動作を確認した

とは表現しないでください。

可能なら完成した、

`device1.zip`

を生成してください。

ZIP直下は`device1/`としてください。

ZIPを生成できない場合は、
必要な全ファイルの全文を出力してください。

## 自己点検

生成後は次だけ確認してください。

- REQUIREMENTS.mdの動きを実現している
- WIRING.mdのGPIOと一致している
- 起動直後が安全な状態
- 存在しないヘッダーやライブラリを使っていない
- USB使用時はrv003usbまたは確認済み参考実装を使用している
- MakefileがDevkitの構成に合っている
- ローカル操作型では可能ならmakeが成功する

問題があれば、
利用者へ返す前に修正できるものは修正してください。

## 出力

問題がなければ最初に、

`プログラム生成OK`

と示し、成果物を生成してください。

本当に利用者または講師の判断が必要な場合だけ、

`要確認`

として停止してください。
