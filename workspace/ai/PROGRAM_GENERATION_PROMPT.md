## 利用経路の判定

利用経路が未記入の場合は、次の条件でだけ判定して構いません。

### ローカル操作型

次をすべて実行できる場合です。

* Devkitのローカルファイルを検索できる
* Devkitのローカルファイルを読み取れる
* `workspace/my/device1`へファイルを書き込める
* ターミナルでコマンドを実行できる

### Web・手動受け渡し型

次に該当する場合です。

* `AI_HANDOFF_MANIFEST.md`または`AI_HANDOFF.md`を受け取っている

利用経路の指定が必要であることを示してください。

### Web・手動受け渡し型

受け取った`AI_HANDOFF_MANIFEST.md`を最初に読み、マニフェストに列挙されたファイルだけを根拠にしてください。

`AI_HANDOFF.md`が単一ファイルとして渡された場合は、その中の`BEGIN FILE`と`END FILE`で区切られた各内容を、記載された元の相対パスのファイルとして扱ってください。

次を仮定してはいけません。

* 受講者PCのローカルファイルを読める
* 添付されていないDevkitファイルを読める
* 添付されていない依存ライブラリを読める
* ツールチェーンを実行できる
* ビルドできる
* ファームウェアを書き込める
* USB認識を確認できる
* 実機動作を確認できる

マニフェストと実際に読めるファイルが一致しない場合、必須ファイルがない場合、または必要な参考実装が収録されていない場合は、プログラム生成を停止して不足内容を列挙してください。

Web受け渡しパックは、受講者がDevkitの`workspace`で次を実行して作成するものです。

```text
python ai/prepare_web_handoff.py
```

* 互換する確認済み参考演習・PoCが1つ以上明示されている
* 参考実装の必要ファイルを実際に読めている
* VIDを確認できる
* PIDを確認できる
* Usage Pageを確認できる
* Usageを確認できる
* 使用するすべてのReport IDを確認できる
* 各Reportの方向・種類を確認できる
* 各Reportの長さを確認できる

修正によって次のいずれかを変更する必要がある場合は、コードだけを変更して解決してはいけません。

* 要件
* 使用部品
* 数量
* GPIO
* GPIO方向
* 配線
* 電源
* 信号電圧
* 論理
* 極性
* 抵抗
* ドライバー
* 保護回路
* USB仕様
* 起動状態
* 停止状態
* 安全条件

その場合は、

1. コード修正を停止する
2. 変更が必要な正本を特定する
3. 正本の修正案を示す
4. 人による再確認が必要であることを示す

という順序にしてください。

電気的安全性に関係する変更の場合は、修正後の`WIRING.md`について人による配線安全確認を再実施してください。

その確認では、

* `確認対象: プログラム修正後の再確認`
* `再確認対象のプログラム版: （対象版）`

を使用してください。

人による確認が完了するまで、修正版コードを安全確認済みとして扱ってはいけません。

Web経路では、古いファイルと新しいファイルが混在しないよう、修正版`device1.zip`全体、または全ファイルの全文を再生成してください。
