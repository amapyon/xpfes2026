# 04_rotary_cursor_haptic

[指定のセンタースイッチ付きロータリーエンコーダーモジュール](https://electronicwork.shop/items/64b9e54b9dd503007bc60458)の回転入力でOSのポインターサイズを変更し、変更できた瞬間に振動で触覚フィードバックを返す必須演習です。

この演習は、`03_vibration_motor_console`を完了した後に行います。`02`で確認した回転入力とカーソルサイズ変更へ、`03`で確認した振動モジュール制御を組み合わせます。振動モジュールを含む配線は`03`の状態を維持します。ファームウェア、USB設定、ホストアプリはWindows/macOS共通です。単一の`host/cursor_size_host.py`が実行時にOSバックエンドを選択します。

## 開始条件

次の項目を`02_rotary_cursor_size`と`03_vibration_motor_console`で確認してから進みます。

- エンコーダーのGND、KEY、S1、S2、5Vの5本が配線済み
- `make app-dry-run`でCW／CCWを受信できる
- `make app`で回転方向に応じてカーソルサイズが変わる
- `Ctrl+C`で終了すると、起動前のカーソルサイズへ戻る
- 振動モジュールのVCC、GND、INが配線済み
- `03`の`make pulse`で短く振動し、自動的に停止する
- `03`の`make off`で振動が停止している

いずれかが成功していない場合は、先に`02`または`03`へ戻って確認します。`04`では配線を追加・変更しません。

## 完成時の動作

- エンコーダーを1クリック回すと、ポインターサイズが1段階変わる
- PC側で変更後の値を確認できた時だけ、振動モジュールが約60ms ONになる
- サイズが上限／下限に達して変化しない時と`make app-dry-run`では振動しない
- `Ctrl+C`で終了すると、起動前のポインターサイズへ戻る

## 検証状態

- 従来の振動なしOS別実装はWindows、macOSとも想定動作を実機確認済み
- 共通ファームウェアへ触覚フィードバックを統合した版は、Windows/macOSとも実機で再確認が必要
- 振動モジュール単体の制御方式はWindows 11 x64とmacOS Apple Siliconで実機確認済み
- 統合後の共通ホストはWindows/macOS実機で再確認が必要
- VID:PID `1209:C005`とシリアル`TEST8-001`はPoC用一時値

## 使用する部品

- `02`から使用しているUIAPduinoとエンコーダーモジュール
- `03`で配線したドライバー回路内蔵の5V振動モーターモジュール

新しい部品やジャンパー線は追加しません。モーター本体をGPIOへ直接接続せず、`03`で使用したドライバー回路内蔵モジュールを継続します。

## 配線

`03`完了時の配線をそのまま使用します。

### `02`から変更しない配線

| UIAPduino | エンコーダー | この演習での扱い |
|---|---|---|
| GND | GND | `02`の配線を維持 |
| D5 / PC3 | KEY | `02`の配線を維持。この演習では未使用 |
| D9 / PC7 | S1 | `02`の回転信号1を維持 |
| D8 / PC6 | S2 | `02`の回転信号2を維持 |
| 5V | 5V | `02`の赤い配線を維持 |

### `03`から維持する振動モジュール配線

| UIAPduino | 振動モジュール | 用途 |
|---|---|---|
| 5V | VCC | モーター電源 |
| GND | GND | エンコーダーと共通のGND |
| D6/A2 / PC4 | IN | 振動ON/OFF制御 |

`04`では配線を追加・変更しません。`5V`と`IN`、共通GNDが`03`の表どおりであることだけを確認します。発熱、異臭、USB切断、連続リセットが発生した場合は直ちにUSBを外します。

## ビルドと書き込み

`03_vibration_motor_console`のフォルダーから`04`へ移動します。

```text
cd ../04_rotary_cursor_haptic
```

`start-uiap`から開いた同じ開発環境で、次を実行します。

```text
make clean
make
make size
make flash
```

この書き込みで、`03`の振動単体ファームウェアは、カーソル操作と触覚機能を持つ`04`のファームウェアへ置き換わります。書き込み直後は、振動モジュールがOFFであることを確認します。連続振動する場合はUSBを外し、`IN`の配線と書き込み対象を確認します。

## 段階確認と実行

```text
make host-doctor
make hidcheck
make app-dry-run
make cursor-test
make app
```

- `make app-dry-run`: ポインターサイズを変更せず、CW／CCWだけを表示します。振動しません。
- `make cursor-test`: OSのポインターサイズ変更と復元だけを確認します。エンコーダー操作を使わないため振動しません。
- `make app`: 変更後の値を確認できた場合、コンソールへ`haptic=ON`を表示し約60ms振動します。
- 上限／下限では`limit`を表示し、振動しません。
- `Ctrl+C`: 起動前のポインターサイズへ戻します。

異常終了後の手動復元:

```text
make restore
```

## HID通信

入力レポートは`[Report ID 1, delta, sequence]`の3バイトです。ホストは移動量を読み、診断用連番を無視します。旧ファームウェアのReport IDなし入力も診断のため受信できます。

ポインターサイズの変更と再読取りに成功すると、ホストはFeature Report `[Report ID 2, 1]`を返します。ファームウェアはこの指示を受けた時だけ`D6/A2`を約60ms Highにします。

## 完了条件

- `02`と同じようにCW／CCWでカーソルサイズが変わる
- サイズが実際に変わった時だけ、短く1回振動する
- 上限／下限とドライランでは振動しない
- `Ctrl+C`終了時に起動前のカーソルサイズへ戻る
- 終了後およびUSB接続直後に振動し続けない
